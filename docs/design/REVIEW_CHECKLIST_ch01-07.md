## 重点チェック（気付き3点の運用）

### 1. 第6章 — 想定実行時間（架空数値リスク）

Opus は空欄を埋めようとする。数値には次のいずれかが必須:

- 修飾語: `概算` / `測定前` / `目安` / `未測定`
- 根拠の明示（例: 「Polymarket CLOB 公式ドキュメントの p99 レイテンシ &lt; 500ms より試算」）
- 試算ロジックの記述

**違反時**: 第8章着手前に **第6章差し戻し**。設計段階の架空数値は後工程で「事実」化しやすい。

### 2. 第7章 7.3 — 第15章への参照

7.3 は日次レポート JSON の **概要のみ**。以下は違反:

- 完全な JSON スキーマの執筆
- 第15章相当のフィールド定義の網羅

正しい止め方: `(→ 第15章で詳細)` と明記して概要に留める。

**違反時**: 該当節を削除し概要のみに戻す。第15章本文の先走りはスコープ違反。

### 3. INDEX.md — 登録範囲

**メイン目次**: 生成済みの7章のみ（ファイル名・1行サマリ・ステータス）。

**任意**: 末尾に `<details>` で「今後の章（タイトルのみ）」を折りたたみ表示可。  
第8〜24章をメイン目次に並べない（統合・分割時の混乱を避ける）。
