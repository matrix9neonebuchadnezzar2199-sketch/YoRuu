ツール名確定・Telegram削除・CLI反映方式の選定 #

2026-05-27 08:22 JST dev tool design ok

概要

Polymarket の BTC 5分 Up/Down 市場に対する自動取引Botのプロジェクト名を YoRuu（ヨルー）に確定。 「夜」+ ループ感のある "uu" で、夜間レビューで進化するシステムという設計思想を音にも反映させた。 同時に、当初想定していた Telegram Bot による通知・操作経路を削除し、よりシンプルな構成（CLI + ローカルファイル + 既存契約の Genspark Opus 4.7）に切り替える判断を行った。

設計判断

Telegram削除で消えるもの

  • Telegram Bot Token / Chat ID 設定
  • Telegram メッセージ送受信処理
  • 返信フォーマット解析・コマンドハンドラ
  • python-telegram-bot 依存

代わりに必要になるもの

  • 毎日決まった時刻に report_YYYY-MM-DD.json をローカルに保存
  • ファイル内に「AI分析用の指示プロンプト」も同梱し、ユーザーがコピペ1回で済むようにする
  • ユーザーが AI から受け取った JSON 結果を どこに貼り付けるか の仕組み

JSON結果の反映方式（3案比較）

方式概要長所短所
方式1 CLI yoruu apply でクリップボードから読み取り → 検証 → 確認 → 反映 実装30行程度・操作最速 クリップボード前提
方式2 ファイル監視 ~/.yoruu/inbox/ に保存 → Bot が自動検知 エディタ派に優しい ファイル監視ループが必要
方式3 Web UI http://localhost:8765/review で貼り付け→検証→反映 視覚的 実装コスト大
decision 方式1（CLI）を採用。実装が軽く、朝のルーチンを 3 ステップ （report をコピー → AI に分析依頼 → yoruu apply 実行）に圧縮できる。将来必要なら方式2のファイル監視を併設する余地は残す。

朝のルーチン（3ステップ）

  1. report_YYYY-MM-DD.json を開いてコピー（または添付）
  2. AI（Genspark Opus 4.7）に貼って分析 → 返ってきた JSON をコピー
  3. ターミナルで yoruu apply 実行 → y で確定

背景

マスターから指定された 5 種類の設計図（シーケンス図 / I/O図 / 操作フロー / 関数呼び出し図 / エラーハンドリング図）に対して、 お金が動くトレーディング Bot 特有の安全要件 を満たすため、追加で必要となる設計図・設計手法を提案し、最終的に 24章構成の設計書 として合意形成中。

マスター指定の設計図（5点）

図目的
シーケンス図時系列での処理の流れと参加者間のやり取り
インプット/アウトプット図ユーザー入力 → システム出力の対応

追加提案（お金が動く系で推奨/必須）

  1. 状態遷移図（State Machine Diagram）★最重要 — 競合状態によるバグを設計段階で排除（例: STOPPED → RUNNING → REVIEWING → APPLYING → RUNNING）
  2. データフロー図（DFD）★重要 — データの出所・加工・保存・利用を可視化、バックアップ戦略にも直結
  3. 信頼境界線図 ★必須 — Polymarket / Binance / AI からの入力は信頼境界線で必ず検証する設計を強制
  4. リスク・セーフガード一覧表（Risk Matrix）★必須 — 事故シナリオ × 影響度 × 発生確率 × 予防/検知/復旧策
  5. 不変条件（Invariants）一覧 — 0.80 ≤ MIN_PROB ≤ 0.95、0 < KELLY_FRACTION ≤ 0.8 等を assert で機械検証可能に
  6. ログレベル・トリアージ表 — エラーコード体系（E_APPLY_001 等）でドキュメント即引きを可能に
  7. テスト戦略マトリクス — ユニット 95%+、統合、バックテスト、ペーパー、カオス、セキュリティ
  8. 設定変更の影響範囲マトリクス — 即時反映 vs 再起動必要を一覧化
  9. UI ワイヤーフレーム / 画面一覧 — ダッシュボード、取引ログ、夜間レビュー、設定、戦略履歴、アラート、モード切替の 7 画面
  10. デプロイ・ロールバック手順書 — コードと strategy.json を別管理で単独ロールバック可能に
  11. キル・スイッチ設計 ★絶対必要 — 1クリック停止、パスワード不要（緊急時に手間取らない）、Web UI ダウン時の予備 CLI 経路
  12. 二重承認設計 — paper → live 切替は「LIVE」と手入力タイプ等
  13. 監査ログ設計 — strategy.json 変更履歴と Opus 4.7 の分析テキストごと append-only で保存
  14. 読み取り専用モード — 戦略変更後の「もし取引していたら」観察用

不変条件（Invariants）リスト

  • I1: current_balance ≥ 0 常に成立
  • I2: 0.80 ≤ MIN_PROB ≤ 0.95
  • I3: 0 < KELLY_FRACTION ≤ 0.8
  • I4: 同一 market_id に対する未決済ポジションは 1 つまで
  • I5: live モード時は initial_balance 比 -30% を超える損失で自動停止
  • I6: strategy.json は必ずバックアップ後に上書き
  • I7: 1分あたりの API 呼び出しは Polymarket CLOB 制限の 50% 以下
